# E 线路研发路线

目标：独立 AI 蒸馏训练工作台，首先为 RPTranslate 科研翻译学生模型提供可复现训练流程。

| 阶段 | 功能与验收 |
|---|---|
| E1.1 | Python 基础工程、配置验证、CLI、跨平台 CPU CI |
| E1.2 | 实验清单、任务状态、日志、可复现配置及设备探测 |
| E2 | 教师模型适配器；Qwen 候选；内置在线搜索与一键下载（Hugging Face / ModelScope）、下载队列、断点续传、缓存、校验、自动注册、许可证记录、本地/远程推理 |
| E3 | 优先实现科研论文在线检索、许可过滤、批量全文下载及自动入库；开放许可数据集在线搜索与一键下载、PDF/Word/TXT/JSONL 语料导入、分段、双语生成、清洗去重、术语保护、人工审核、数据集版本 |
| E4 | 读取 D 线真实模型规范、学生网络及分词器适配、权重形状验证 |
| E5 | 序列级蒸馏优先；真实训练更新；再按分词器兼容性研究 logits 和特征蒸馏、多教师 |
| E6 | PyTorch CPU/GPU 训练、CUDA、混合精度、梯度累积、断点续训；按需要支持多 GPU |
| E7 | 固定独立测试集、BLEU/chrF/COMET（适用时）、人工盲测、术语/数字/公式及漏译检测、速度内存测试 |
| E8 | FP32/FP16/INT8 转换、校准、质量回归；INT4 与剪枝须验证 D 线支持 |
| E9 | RPTranslate 模型包导出、版本与哈希、真实 Rust 推理验证 |
| E10 | 按性能剖析逐步引入 Rust 高性能数据处理和自主计算；不强制重写 PyTorch |
| E11 | Electron/React/TypeScript GUI、模型/语料/论文采集与下载中心/任务/监控/评测/导出界面、暂停恢复、远程训练管理 |
| E12 | 完整安装包、真实 GPU 蒸馏、质量及性能对照、综合发布验收 |

每阶段提交独立测试与交接记录，CI 成功后再进入下一阶段。CPU CI 不能代替 GPU 训练实测。所有演示数据须明确标记，不虚报准确率。教师模型不预先锁死，使用前核查许可、评测效果与硬件预算。
